## The one finding (borderline)

`CreditReformBilanzampel` · `core/parsers/csv_balance_sheet.go:276` ·
`parseMonetaryValue` · High tier ("comma strip + strconv parse").

The function is a **locale-aware dual-format monetary parser**: separators
come from parser config (`p.thousandSeparator` / `p.decimalSeparator`), and it
normalizes German (`1.234.567,89`) and English (`1,234,567.89`) formats. The
English-format branch contains a literal `strings.ReplaceAll(x, ",", "")` +
`strconv.ParseFloat` pair, which is what matched.

**Verdict: borderline false positive by suggestion.** The detected pattern is
genuinely present (the English sub-branch IS a hand-rolled ParseCommaf), but
the function's primary purpose is locale-aware parsing, which
`humanize.ParseCommaf` does not cover — following the suggestion wholesale
would break German-format handling.

**Triage guidance for this class:** when a function handles configurable or
multiple decimal/thousands separators, suppress with
`//nolint:gohumanize:H010 // locale-aware parser` rather than refactoring.
A syntactic negative filter was considered and rejected: separators arrive as
variables/fields, so distinguishing "locale-aware" from "plain US-format
strip" reliably needs type information the AST path does not have. With n=1
the honest answer is documented triage, not a speculative filter.

## Assessment

- The rule is **quiet**: one finding across 169 repos, zero Full-tier hits,
  zero clear false positives. The multi-signal requirement (strip AND parse)
  is doing its job.
- Corpus contains few comma-parsing hand-rolls; most numeric CSV code either
  uses configurable separators (gray zone above) or already parses raw values.
- Combined with the 4-class negative fixture corpus (CSV split, space strip,
  display-only strip, comma-rejecting validator), the FP surface is small and
  characterized.
- **Ship decision: keep H010 enabled-by-default** (policy D3 satisfied:
  multi-signal + Full tier, 4-class negative corpus, sweep done same day,
  this document is the "sweep pending" follow-up).

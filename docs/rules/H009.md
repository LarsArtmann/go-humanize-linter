# H009 — manual-commaf

Detects hand-rolled float-with-thousands-separator formatting that should use
`humanize.Commaf` instead of `fmt.Sprintf("%.Nf")` plus a manual comma loop.

## Triggers

The rule fires when a function contains **both** of these signals:

| Signal                                                                                                      | Required |
| ----------------------------------------------------------------------------------------------------------- | -------- |
| `fmt.Sprintf("%.Nf", x)` or `strconv.FormatFloat(..., N)`                                                   | Yes      |
| Manual separator writing (`WriteString(",")`, `WriteByte(',')`, `WriteRune(',')`, `strings.Join(..., ",")`) | Yes      |

Either signal alone is insufficient. The combination is a near-certain
reimplementation of `humanize.Commaf`.

> **Note:** Functions flagged by H009 may also trigger H002 (manual comma
> formatting) because the comma-grouping loop overlaps. Both diagnostics are
> correct — the code reimplements both `humanize.Comma` and `humanize.Commaf`.

## Real-world examples flagged

```go
// fmt.Sprintf("%.2f") + manual comma insertion
func formatAmount(f float64) string {
    s := fmt.Sprintf("%.2f", f)
    dot := strings.Index(s, ".")
    intPart := s[:dot]
    fracPart := s[dot:]

    var b strings.Builder
    for i, r := range intPart {
        if i > 0 && (len(intPart)-i)%3 == 0 {
            b.WriteString(",")
        }
        b.WriteRune(r)
    }
    b.WriteString(fracPart)
    return b.String()
}
```

## Fix

Use the right humanize function:

```go
return humanize.Commaf(1234567.89)   // "1,234,567.89"
return humanize.CommafWithDigits(1234.5, 3) // "1,234.500"
```

# H004 — manual-plural

Detects English pluralization that should use `humanize.Plural` or
`humanize.PluralWord`.

## Triggers

A function fires H004 when it contains **either**:

1. `if x == 1` switch with the branch body producing a string AND the function
   returns `string` or `[]string`
2. Function parameters named `singular` AND `plural`

### Two-stage false-positive filter

- **Branch must contain a string literal or string concatenation** — rules
  out percentile / exit-code / codegen patterns that look like pluralization
  but don't produce text
- **Function must return string** — rules out validation / error-handling
  functions that compare `n == 1` but don't return a noun phrase

## Real-world examples flagged

```go
// n == 1 with string branch
if n == 1 {
    return fmt.Sprintf("%d item", n)
}
return fmt.Sprintf("%d items", n)

// singular/plural params
func format(singular, plural string, n int) string {
    if n == 1 {
        return fmt.Sprintf("%d %s", n, singular)
    }
    return fmt.Sprintf("%d %s", n, plural)
}
```

## Fix

```go
return humanize.Plural(n, "item", "items", true)       // with count
return humanize.PluralWord(n, "item", "items", true)  // without count
```

## Suppression

```go
//nolint:gohumanize:H004
```

## Validation

- **24 real findings** across the validation sweep
- ~0% false positive rate after the two-stage filter was added
- Earlier: 44 findings with ~60% FP rate

# H001 — manual-bytes-format

Detects hand-rolled byte-size formatting that should use `humanize.Bytes` or
`humanize.IBytes` instead of dividing by 1024 and emitting unit strings.

## Triggers

The rule fires when a function contains **any** of these signal clusters:

| Signal                                     | Confidence |
| ------------------------------------------ | ---------- |
| `"KMGTPE"[exp]` index expression           | Full       |
| `[]string` literal with 2+ byte-unit names | Full       |
| 3+ distinct byte-unit strings in body      | High       |
| 2+ byte-unit strings + division by 1024    | High       |
| 2+ byte-unit strings (no division)         | Medium     |

The byte-unit string set is: `KB`, `MB`, `GB`, `TB`, `PB`, `EB`, `KiB`, `MiB`,
`GiB`, `TiB`, `PiB`, `EiB`, `kB`. Word-boundary regex prevents false
positives like `MEDIUMBLOB` matching `MB`.

## Real-world examples flagged

```go
// KMGTPE index trick
for n := bytes / unit; n >= unit; n /= unit {
    div *= unit
    exp++
}
return fmt.Sprintf("%.1f %cB", float64(bytes)/float64(div), "KMGTPE"[exp])

// Unit slice
units := []string{"B", "KB", "MB", "GB", "TB"}
return units[exp]
```

## Fix

Use the right humanize function:

```go
return humanize.Bytes(uint64(n))   // SI (KB, MB, GB, TB)
return humanize.IBytes(uint64(n))  // IEC (KiB, MiB, GiB, TiB)
```

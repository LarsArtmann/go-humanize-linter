# H008 — manual-ordinal

Detects hand-rolled ordinal suffix formatting that should use `humanize.Ordinal`
instead of switching on `n%10` and returning `"st"`/`"nd"`/`"rd"`/`"th"`.

## Triggers

The rule fires when a function contains a `switch` on `n % 10` or `n % 100`
whose case branches return at least **3 of the 4** English ordinal suffixes
(`"st"`, `"nd"`, `"rd"`, `"th"`). Using 3-of-4 (not 4-of-4) avoids false
negatives on code that maps the exception cases (11/12/13) onto a shared
`"th"` return.

| Signal                                        | Threshold |
| --------------------------------------------- | --------- |
| `switch n%10` with 3+ ordinal suffix returns  | 3 of 4    |
| `switch n%100` with 3+ ordinal suffix returns | 3 of 4    |

## Real-world examples flagged

```go
// Classic switch-on-last-digit
func ordinal(n int) string {
    switch n % 10 {
    case 1:
        return "st"
    case 2:
        return "nd"
    case 3:
        return "rd"
    default:
        return "th"
    }
}
```

## Fix

Use the right humanize function:

```go
return humanize.Ordinal(0)   // "0th"
return humanize.Ordinal(1)   // "1st"
return humanize.Ordinal(2)   // "2nd"
return humanize.Ordinal(3)   // "3rd"
return humanize.Ordinal(11)  // "11th"
return humanize.Ordinal(103) // "103rd"
```

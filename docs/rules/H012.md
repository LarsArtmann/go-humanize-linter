# H012 — manual-word-series

Detects hand-rolled word-series joining (`"a, b, and c"`) that should use
`humanize.WordSeries` / `humanize.OxfordWordSeries`.

Added after corpus research (2026-09-18) found a real hand-roll: a
`parts[0] + " and " + parts[1]` / `Join(parts[:len(parts)-1], ", ") + ", and " + ...`
helper that is a line-for-line `WordSeries` clone.

## Triggers

A function fires H012 when it contains **both**:

1. A comma `strings.Join` (separator `", "` or `","`)
2. A conjunction string literal: `" and "`, `", and "`, `" or "`, `", or "`, ...

Confidence rises with more of the full clone present:

| Form                                                              | Confidence |
| ----------------------------------------------------------------- | ---------- |
| Prefix join `Join(x[:len(x)-1], ", ")` + conjunction + `x[len(x)-1]` | Full   |
| Comma join + conjunction + `len(x)==1`/`len(x)==2` branches       | High       |
| Comma join + conjunction only                                     | Medium     |

## Negative filters

- A plain `strings.Join(x, ", ")` without a conjunction literal stays clean —
  a simple list join, not a word series
- Prose `" and "` concatenation with no `strings.Join` stays clean
- Non-comma separators (`Join(parts, "/")`) stay clean

## Real-world example flagged

```go
func joinWords(parts []string) string {
    if len(parts) == 1 {
        return parts[0]
    }
    if len(parts) == 2 {
        return parts[0] + " and " + parts[1]
    }
    return strings.Join(parts[:len(parts)-1], ", ") + ", and " + parts[len(parts)-1]
}
```

## Fix

```go
return humanize.WordSeries(parts, "and")      // "a, b and c"
return humanize.OxfordWordSeries(parts, "and") // "a, b, and c"
```

## Suppression

```go
//nolint:gohumanize:H012
```

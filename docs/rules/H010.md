# H010 — manual-comma-parse

Detects manual comma-grouped number parsing (`"1,234,567"` → `int64`/`float64`)
that should use `humanize.ParseComma` / `humanize.ParseCommaf`
(go-humanize v1.1.0+). The inverse operation (inserting commas to format a
number) is [H002](H002.md).

Added after go-humanize v1.1.0 introduced `ParseComma`/`ParseCommaf` — before
that release no library function covered this hand-roll.

## Triggers

A function fires H010 when it contains **both**:

1. A comma-stripping signal:
   - `strings.ReplaceAll(x, ",", "")` or `strings.Replace(x, ",", "", n)`
   - `strings.Split(x, ",")` **and** `strings.Join(y, "")` in the same function
   - a `','` comparison combined with a string rebuild (`append` or Builder
     `Write*`) — a comma-filter loop
2. A corroborating number parse: `strconv.Atoi`, `ParseInt`, `ParseUint`,
   `ParseFloat`, or `ParseComplex`

Either signal alone matches thousands of innocent functions (CSV splitting,
display cleanup, comma-rejecting validators); together they match
reimplementations of `ParseComma`/`ParseCommaf`.

## Confidence

| Form                                                  | Confidence |
| ----------------------------------------------------- | ---------- |
| Strip call inlined in the strconv parse call          | Full       |
| Comma strip anywhere + strconv parse in same func     | High       |
| Indirect strip (Split+Join, rune-filter loop) + parse | Medium     |

## Negative filters

- CSV field parsing: `strings.Split(line, ",")` without a `Join(y, "")`
  rebuild stays clean
- Non-comma stripping (`ReplaceAll(s, " ", "")`) stays clean
- Comma stripping without any strconv parse (display cleanup) stays clean
- Comma-rejecting validators: a `','` comparison with no string rebuild
  ("commas not allowed" error paths) stays clean

## Real-world examples flagged

```go
// Strip inlined in the parse call — a one-expression ParseComma clone
func parseCount(s string) (int64, error) {
    return strconv.ParseInt(strings.ReplaceAll(s, ",", ""), 10, 64)
}

// Strip to a variable, then parse
cleaned := strings.Replace(s, ",", "", -1)
return strconv.ParseFloat(cleaned, 64)
```

## Fix

```go
n, err := humanize.ParseComma("1,234,567")    // (int64, error)
f, err := humanize.ParseCommaf("12,345.67")   // (float64, error)
```

Both require go-humanize v1.1.0 or later.

## Suppression

```go
//nolint:gohumanize:H010
```

## Validation

- Positive and negative fixtures in `testdata/h010_*` (all four negative
  look-alike classes covered)
- Real-world sweep (2026-09-18, 169 repos): **1 borderline finding, 0 clear
  false positives, 0 Full-tier hits** — the rule is quiet and the multi-signal
  gate holds. The single hit was a locale-aware dual-format monetary parser
  where the English sub-branch matched; triage guidance for that class is in
  `docs/validation/2026-09-18_h010-sweep.md`.

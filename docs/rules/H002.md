# H002 — manual-comma-format

Detects manual comma / thousands-separator insertion that should use
`humanize.Comma` or `humanize.Commaf`.

## Triggers

Two detection paths:

1. **Strong**: `mod-3` (or `step-by-3`) grouping + comma/dot/space separator
   written via `WriteString`, `WriteByte`, `WriteRune`, or `strings.Join`.
2. **Fallback**: for-loop + separator + `strconv.Itoa` / `FormatInt` /
   `FormatUint` / `FormatFloat` (catches cases where the step size is a named
   constant like `digitsPerGroup`).

## Confidence levels

| Path                          | Confidence |
| ----------------------------- | ---------- |
| Both mod-3 AND step-3 signals | Full       |
| Either mod-3 OR step-3        | High       |
| Fallback only                 | Medium     |

## Real-world examples flagged

```go
// mod-3 grouping
if len(s) > 0 && (len(s)-i)%3 == 0 {
    result.WriteString(",")
}

// step-by-3 loop
for i := 0; i < n; i += 3 {
    b.WriteString(",")
}
```

## Fix

```go
return humanize.Comma(int64(n))   // integer with commas
return humanize.Commaf(3.14)       // float with commas
```

## Suppression

```go
//nolint:gohumanize:H002
```

- **7 real findings** across the validation sweep

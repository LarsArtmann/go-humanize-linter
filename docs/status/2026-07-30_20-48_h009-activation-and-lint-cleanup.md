### Process

1. **The TODO_LIST.md was stale for at least one merge cycle.** H008 was merged (commits `bd9164e`/`4db95d1`/`e3ef534`) and H009 was implemented-but-not-registered, but TODO_LIST didn't move from "planned" until this session. The status reports (`docs/status/2026-07-30_19-27_*.md` and `…19-28_*.md`) flagged both states but nobody reconciled them. Add a CI test that diff-checks the rule-count in `linter_test.go` (`!= 9`) against `len(rule_*.go)` minus the shared `rule_ordinal.go`-and-`rule_commaf.go`-and-`rule_helpers.go` files — anyone landing a new rule will be forced to update both.
2. **The "ghost rule" detection gap.** A future PR could land `rule_foo.go` + `pattern_foo.go` + `testdata/...` without registering in `rules.go`. The only way to catch it today is a manual diff audit. Two cheap tests would close the gap: (a) `TestAllRulesDetectorCoverage` — assert `len(ruleIDs(rule_*_test.go)) == len(ruleXxxFactories())`, (b) `TestNoGhostRuleFiles` — assert every `rule_*.go` file with a `Rule*Func()` factory has an entry in `AllRules()`.
3. **Status reports aren't being read.** This session discovered 9 lint issues that were documented as "9 remaining issues in new pattern files" in `docs/status/2026-07-30_19-28_mass-todo-execution.md` 80 minutes earlier. The note was there but the next session didn't pick it up. Either `(a)` auto-promote open items from `docs/status/*.md` into `TODO_LIST.md` on session open, or `(b)` add a pre-commit hook that surfaces "items mentioned in the last status report that are not in TODO_LIST.md".
4. **AGENTS.md wasn't updated when H008 landed.** Same root cause as (1): merges were happening without a docs-touch checklist. Add a checklist to `CONTRIBUTING.md` (currently only 14 lines) that mandates updating AGENTS.md / TODO_LIST.md / CHANGELOG.md when adding a rule, detector, CLI flag, or new public type.

### Code Quality

5. **`cmd/go-humanize-linter/main.go` rule-ID constants duplicate `pattern_helpers.go`.** Promote them: export `ruleIDH001`–`ruleIDH009` from the `humanizelint` package as `RuleIDH001` etc., and have `main.go` import + use them. Adds an explicit dependency from the CLI on the core package's IDs but eliminates a class of "added a rule, forgot to update the map keys" bugs.
6. **`pattern_commaf.go` extracted helpers lack unit tests.** The four new pure functions are trivially testable: `walkFormatFloatVerbs`, `scanDottedPercentFloat`, `scanBarePercentFloat`, `hasFormatFloatPrecision`. A 4-case `TestWalkFormatFloatVerbs` covering `%%` escapes, mixed-width verbs, and trailing junk would catch every realistic H009 regression in <50 lines.
7. **`mnd` allows `%f`-style format verbs but not the `dotPrecisionOffset = 2` arithmetic.** The refactor introduced a small number of named constants (`minFormatWalkRange`, `minPercentWidth`, `dotPrecisionOffset`) that read more like "magic numbers with names" than real domain constants. A short `// range arithmetic for the format-string walker — kept literal to avoid hiding the i, i+1, i+2, i+3 access pattern from the reader.` comment would defend the choice better than the names alone.
8. **`pattern_helpers_test.go`'s `boolSrcCase` is the first shared struct in this file.** If a third test needs it, the file's organization will need an explicit "test fixtures" section. For now it's fine — the type sits at the top and is reused by both test functions.
9. **`h009_commaf/main.go` (testdata) is hand-written.** Same for the `analysistest/h009positive/main.go`. If the format-string-walker logic ever changes, these fixtures will need to be updated by hand to keep producing a finding. Consider a generator script in `testdata/scripts/gen_h009.go` that produces fixtures from a spec.

### Architecture

10. **`rules.go`'s `byID` map is rebuilt every `NewHumanizeDetector` call.** The lookup table is `package var` candidate material — build it once in `init()` and freeze. Hot path currently re-allocates a map per detector instance which doesn't matter for one-shot CLI runs but would matter if the plugin path is invoked many times per package.
11. **`checkFuncDecls` walks the filesystem twice when the registry runs every rule.** Each rule is its own `RuleFunc` and gets its own walk. With 9 rules that's 9 walks of the same directory tree on a large codebase. A future optimization: one walk, one parsed-file cache, 9 detectors invoked in sequence against the cached AST.
12. **`walker.go`'s `checkFuncDecls` swallows parse errors with `//nolint:nilerr`.** This is a deliberate choice ("syntax errors are the compiler's job"), but it means a malformed file in a customer's repo will produce 0 findings for ALL rules silently. Consider adding a `walkStats` struct that tracks `(filesParsed, parseErrors, filesSkipped)` so the CLI summary line can include them.

### Tests

13. **`TestDefaultRegistry_AllRules` asserts `len == 9` — but `TestAllRules_CleanCode` (if it exists) wasn't reviewed.** Either it doesn't exist (then add one — every rule's positive fixture must pass when run against the full registry) or it does and I missed it.
14. **`TestRuleCommaf_Positive` has no negative mirror.** Add `TestRuleCommaf_Negative` that runs `hasCommafPattern` against `fmt.Sprintf("%%d", x)` (no `%.Nf`), `fmt.Sprintf("%.Nf")` ALONE (no separator loop), and the separator loop ALONE (no float format) — all three should return false.
15. **`TestRuleOrdinal_Positive` likewise has no negative.** A clean `switch n { case 1: return "1st"; case 2: return "2nd" }` (no `%` operator) should not flag. Add that fixture.
16. **`TestWalkFormatFloatVerbs` is the most valuable missing test in this session.** Without it, any future refactor of the format-string walker could silently regress H009 to 0 detections. 4 lines of input table.

### Documentation

17. **CHANGELOG.md 0.2.0 section has no published release notes.** I wrote Changed/Fixed entries but did not draft a `release-notes/0.2.0.md` for the GitHub Release.
18. **`docs/rules/H008.md` and `docs/rules/H009.md` don't exist.** The 0.2.0 release advertised them in the CHANGELOG ("Markdown docs per rule: `docs/rules/H001.md` through `H007.md`" — but H008/H009 were left out because they were "landed later"). User-facing docs for the new rules are missing.
19. **`README.md` rule table is stale** if it references H001-H007 without H008/H009. Did not check.

### CI / Tooling

20. **`nix run .#lint`'s `grep -v` filter is a band-aid.** It hides a real signal ("the project uses linters golangci-lint can't validate") from one persona (the dev shell) while a CI run with raw `golangci-lint` still sees it. Fix it properly with `.golangci.yml`'s `plugins:` map or by exporting `ruleIDHxxx` so they go through the standard `//nolintlint` validation path.
21. **No CI step asserts `nix run .#lint` returns 0 issues.** Currently the CI workflow may or may not run lint; if it does, the grep-filtered output might still leave residual issues that aren't surfaced. Add an explicit `nix run .#lint` GitHub Action step that uploads the result.

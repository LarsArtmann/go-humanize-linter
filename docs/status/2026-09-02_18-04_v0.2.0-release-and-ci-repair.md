## e) WHAT WE SHOULD IMPROVE

1. **Commit-significant-work-immediately**: the auto-daemon is a safety net, not a ghostwriter. Anything load-bearing gets a hand-written message within minutes of turning green.
2. **Verify-external-claims at the claim site**: the c084fd9 test lie happened because a docs-sync trusted a prose claim. This session re-verified against primary sources (published module source + sweep doc) — that should be the default reflex whenever a test is aligned to a _claimed_ dependency behavior.
3. **Falsification experiments before theory-hopping**: the misspelled-directive probe (2 minutes) settled what two theory cycles didn't. Do the differential experiment first.
4. **CI debugging protocol**: for auth/env issues, ship `ssh -G`/`git config -l` diagnostics in the first attempt, not the fifth.
5. **Secrets lifecycle rule**: create-new → verify → switch-reference → delete-old. Never the reverse.
6. **Tool selection discipline**: YAML/shell content edits via `edit` with exact strings; reserve scripting for genuinely mechanical bulk work — especially when backslashes are in play.
7. **`GOWORK=off` as a first-class local gate**: it correctly predicted CI behavior all session (workspace siblings differ from pins). Consider a flake check that runs the suite both ways.
8. **The go.work drift class** (T20) deserves a standing check, not a one-off note — workspace vs pin divergence is how the test lie survived as long as it did.
